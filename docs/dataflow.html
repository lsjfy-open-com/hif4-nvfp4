HiF4 高精度适配 NVFP4 · 数据流

不是把 NVFP4 比特原样搬到昇腾，而是把 NVFP4 的 recipe（block-16、E4M3、可选 PTS）编译进 HiF4 的 encoding（block-64、E6M2 + 微指数）。图按 形式模型 画，数字来自文献，不是本仓库新测。

1. 总览：三条假设走不同的路

同一套线性层输入，三种适配。H1 吃满 Cube 64-dot；H2 先按 NVIDIA 配方再塞进 HiF4 位布局；H3 按模块拆。

2. NVFP4 解码流

x = E2M1 · sblock · sglobal。每 16 个数共享一个 FP8 E4M3；整个 tensor 再乘一个 FP32。E4M3×E2M1 盒子只有约 22 binades，所以常先把峰值收到 2688（PTS）。

训练 extras（不是格式本身）：梯度随机舍入 SR、wgrad 上 RHT d=16、scale swizzle、GEMM 只支持 TN。H1 不要原样搬 SR。

3. HiF4 解码流

Vi = E6M2 · 2(E1_8 + E1_16) · S1P2i。一组 64 个数 + 32 bit 元数据。微指数是 2 的幂，组 scale 是 E6M2（bias 48），全局约 69 binades，一般不用 PTS。

Intra-group 最大 7、最小 0.25（4.81 binades）。E2M1 的 {0.5,1,1.5,2,3,4,6} 能落到这个网格上，但四个数必须共用同一个 (E1_8, E1_16)，这是 H2 嵌不进去的主因之一。

4. H2：四个 NVFP4-16 打进一个 HiF4-64

Cube 一次吃 64 长点积，所以要把 4 个 NVIDIA 块塞进 1 个昇腾 unit。存储可以这么排，数值一般对不齐：E4M3 有小数尾数，HiF4 微指数只有 {1,2,4}。

NVFP4 块 有损重编码 HiF4 unit（Cube 真正吃的）

cpu-ref 上精确命中约 6.8%。仿真要分清两件事：存储仿真（位布局像 HiF4）和 compute 仿真（硬件仍按一套 E6M2+E1 做点积，不会真的用四套 E4M3）。

5. 一层里：linear 和 attention 不是同一条河

HiF4 论文的 PTQ 只量化投影 GEMM。NVFP4 预训练也把 QK/PV 留高精度。Full-Stack FP4 才把 QKᵀ 做成 NVFP4，并且 PV 仍是 BF16。适配时必须拆开画。
